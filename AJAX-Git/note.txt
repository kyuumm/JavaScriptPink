git ls-files//查看更改的文件

git status -s//查看文件状态，
两个字母显示，第一是暂存区状态，二是工作区状态
U未跟踪，A暂存区新添加的文件，M被git追踪但是有改动的文件
git restore //暂存区文件覆盖工作区

git rm --cached 目标文件//暂存区移除文件

git log --oneline//查看提交历史
git log //两者区别：oneline只有一行，更简洁，下面的比较详细但是显示的信息少

git reset --soft 版本号//旧版本有的文件覆盖，新版本添加的文件保留
git reset --hard 版本号//完全覆盖工作区暂存区
git reset --mixed 版本号 (==git reset)//覆盖暂存区，保留工作区
git reflog 查看完整日志， 包括回退之后消失的log

分支：
默认是HEAD->master，是指针，
分支的作用：开发新需求/修复bug
1创建新分支   git branch 分支名 
2切换分支命令 git checkout 分支名，让HEAD指向新分支
3写代码

**分支合并和删除
1切回要合入的分支git checkout master
2合并分支 git merge test
3删除合并后的分支指针 git branch -d test

删除了test分支

出现冲突：用git status查看
保留其中一方：git add 文件名
或者打开文件查看具体要保留的行

合并与提交：
master分支有新提交，分支也有新提交，也就是分叉点互相离开了
git会自动使用多个快照记录合并后产生一次新的提交
1切回要合入的分支git checkout master
2合并分支 git merge test2
3删除合并后的分支指针 git branch -d test2

合并之后的顺序是按照提交的时间顺序

发生合并冲突，需要打开vscode手动处理代码，并重新add ，commit提交

（提交记录太多可以按enter继续显示，也可以按q退出，clear是清屏）

git -v查看git版本
git init初始化仓库

git status 查看文件状态（俩字母）详细版
git status -s 查看文件状态简陋版
git ls-files暂存区查看文件

git log查看提交记录详尽版
git log --oneline查看提交记录。简略版

git checkout -b 创建并立刻切换分支
git merge 分支名 //把分支提交历史记录合并到所在分支
